## 仍需运维处理

### P0：后端基础镜像损坏

当前 `mvp-skeleton-backend:latest` 带有错误的 `/app/alembic.ini` volume 声明，导致新 worker 容器无法正常创建。现有后端及 worker 仍在运行，但一旦必须重建容器会有恢复风险。需要在低峰期先增加 swap，再重建镜像并逐个替换容器。

### P0：内存余量低且无 swap

服务器总内存约 1.6GB，可用约 263MB，未配置 swap。当前负载低且没有 OOM 记录，但 Docker 构建或多个服务同时重启可能触发 OOM。

### P1：worker 健康状态尚未落到现有容器

compose 中已修复 worker 健康检查，但当前 collection/publish worker 仍是旧容器，因此 Docker 显示 unhealthy；进程实际存活且当前队列空闲。必须在镜像修复后才能安全重建并应用新健康检查。

### P1：历史发布任务待收口

- 发布任务 #38（草稿 #904）仍为“结果待核对”，但后续任务 #39 已成功发布同一草稿，应增加安全的历史任务收口动作，避免诊断页持续报警。
- #7、#19、#33 仍为历史未知结果，不能自动重发，应由操作员核对后确认未创建或绑定已创建商品。
- #37（草稿 #995）为旧的配置缺失记录；当前若配置已保存，应通过新任务发布，不修改历史证据。

### P2：OAuth 状态展示可更准确

数据库中的 access token 到期时间已经过去，但系统会在实际调用时使用 refresh token 刷新。当前 readiness 只统计店铺行数，不区分启用、已连接、令牌是否可刷新，容易让“3 个 connected stores”产生误解；建议增加 `enabled_connected_stores` 和最近刷新状态。
